# 一、认识 Elenchi

## 1. Elenchi 是什么？

Elenchi 是一款**本地优先的 AI 学习应用**。你可以导入自己的 Markdown 教材，Elenchi 会帮助你把教材整理成章节、知识点和课程，然后通过苏格拉底式对话，帮助你回忆、解释、验证和应用这些知识。

它的核心目标不是替你快速读完教材，而是：

> **用追问把知识真正想通。**

一个完整的学习闭环是：

```text
导入教材
  → 章节准备
  → 知识点抽取
  → 覆盖检查
  → 课程编排
  → 苏格拉底式对话
  → 回答评估
  → 提示、追问或反例
  → 掌握记录与课程收尾
```

## 2. Elenchi 适合谁？

Elenchi 更适合以下学习场景：

- 你已经有教材、讲义或学习笔记，希望围绕原文学习；
- 你不满足于只看摘要，希望自己解释、推理和应用；
- 你正在学习概念、原理、方法或事实类知识；
- 你希望 AI 像一位耐心的私教一样追问，而不是一次性倾倒答案；
- 你希望课堂记录和学习材料保存在自己的设备上。

它尤其适合需要理解和迁移的内容，例如：

- 编程与计算机科学
- 数学、统计学和机器学习
- 自然科学教材
- 语言学习材料
- 专业考试的理论内容
- 结构清晰的 Markdown 讲义和课程笔记

## 3. Elenchi 是聊天机器人吗？

不是传统意义上的聊天机器人。

虽然课堂界面采用对话形式，但每一轮对话都受到课程目标、知识点、教材证据和学习状态的约束。系统会先评估你的回答，再决定下一步应该：

- 澄清问题；
- 追问你的假设；
- 要求你给出理由或证据；
- 提供反例；
- 给出逐步提示；
- 要求你应用到新情境；
- 推进到下一个知识点；
- 或结束本课。

因此，课堂的重点不是“和 AI 聊得久”，而是完成一个个可验证的认知动作。

## 4. Elenchi 会替我读完整本书吗？

不会以“替你读完并生成一篇总结”的方式工作。

Elenchi 会帮助你整理教材、识别知识点并设计学习路径，但学习过程仍然需要你回答问题、解释概念、举例、比较和应用。系统会根据你的回答调整提示强度，但不会把学习者完全排除在理解过程之外。

# 二、开始使用

## 5. 开始使用 Elenchi 需要准备什么？

你需要：

1. 一份 Markdown（`.md`）格式的教材、讲义或笔记；
2. 一个可访问的 OpenAI 兼容 API 服务；
3. 该服务的 Base URL、API Key 和模型名称；
4. 能够连接到该服务的本地 Elenchi 服务。

Elenchi 当前使用 OpenAI 兼容的 Chat Completions 接口。不同服务对模型能力、上下文长度、JSON 输出质量和费用的支持可能不同。

## 6. 第一次使用的步骤是什么？

通常可以按以下顺序操作：

1. 打开 Elenchi 的设置页；
2. 填写 AI 服务的 Base URL、API Key 和模型名称；
3. 使用“测试连接”确认服务可用；
4. 保存设置；
5. 导入 Markdown 教材；
6. 打开教材并选择一个章节；
7. 点击开始备课；
8. 等待知识点、覆盖审计和课程列表生成；
9. 选择一堂课进入课堂；
10. 根据 AI 的问题，用自己的话回答。

备课和课堂都需要已配置的 AI 服务。

## 7. 支持哪些教材格式？

当前 MVP 主要支持：

- Markdown 文件（`.md`）；
- 使用 Markdown 标题组织章节和小节的教材；
- 纯文本、段落、列表、代码片段等 Markdown 内容。

当前不把以下格式作为已支持能力：

- PDF；
- EPUB；
- Word（`.doc` / `.docx`）；
- 扫描图片或 OCR 文档；
- 需要复杂版式还原的电子书。

如果你的教材是其他格式，建议先将其转换为 Markdown，并检查标题层级、公式、代码和列表是否仍然正确。

## 8. AI 服务必须是某一家供应商的吗？

不要求使用某一家供应商，但服务需要提供与 OpenAI Chat Completions 兼容的接口，并支持 Elenchi 使用的文本生成调用。

兼容性取决于具体服务。常见风险包括：

- Base URL 不是兼容接口的根地址；
- API Key 无效或权限不足；
- 模型不支持当前上下文长度；
- 模型返回的 JSON 结构不符合要求；
- 服务不支持流式回答；
- 服务发生限流、超时或网络错误。

建议先使用“测试连接”，再导入较短的教材章节验证完整流程。

## 9. 我可以更换模型或 Base URL 吗？

可以。设置页支持修改 Base URL、模型名称和 API Key。

如果只修改 Base URL 或模型名称而不重新输入 API Key，系统会继续使用已保存的 Key。界面只显示脱敏后的 Key 预览，不会把完整 Key 回显出来。

# 三、教材如何被整理

## 10. 教材、章节、小节和课程有什么区别？

它们是教材处理和学习组织中的不同层级：

```text
教材
└── 章节
    └── 小节
        └── 知识点

课程 = 按顺序组织的一组知识点
```

更准确地说，课程由若干按顺序组织的知识点组成：

- **教材：** 你导入的完整 Markdown 文件；
- **章节：** 教材中的较大内容单元，例如“第一章 监督学习”；
- **小节：** 章节内部的教学内容单元，例如“1.1 监督学习的定义”；
- **知识点：** 可以单独提问、解释和评估的原子命题；
- **课程：** 根据认知容量和教材顺序，把若干知识点安排在一起的一次学习单元。

因此：

> **一章不等于一堂课。一章可能被安排成多堂课。**

## 11. Elenchi 如何切分章节？

教材导入时，Elenchi 首先识别章节标题，并将较大的章节内容分开。章节内部的二级、三级标题会保留，供后续备课使用。

在备课阶段，系统会进一步识别章节内部最合适的小节边界：

- 如果章节有明确的子标题，通常按最浅的子标题切分；
- 更深层的标题会保留在所属小节中；
- 没有子标题的章节会作为一个小节处理；
- 章节标题后的导语可以作为独立的章节导语；
- 目录式的空标题会尽量折叠到后续有正文的小节中；
- 分节逻辑会尽量保证原文内容不被静默丢弃。

切分的目标不是把文本切得越碎越好，而是形成适合抽取知识点和开展课堂教学的内容边界。

## 12. 如果我的 Markdown 标题层级不规范，会发生什么？

Elenchi 会尽量根据实际出现的标题结构处理，但标题层级不规范可能影响：

- 章节识别；
- 小节边界；
- 知识点的所属小节；
- 课程的主题分组。

建议使用清晰、连续的标题层级，例如：

```markdown
# 第一章 监督学习

## 1.1 基本概念

### 1.1.1 标签

## 1.2 训练过程
```

如果导入后章节或小节划分明显不合理，可以先调整 Markdown 标题，再重新导入教材。

## 13. 为什么不直接把整章内容发送给 AI？

整章注入看似简单，但会带来几个问题：

- 上下文过长，成本和延迟增加；
- AI 容易在多个主题之间失焦；
- 课堂问题不容易对应到具体知识点；
- 难以判断哪些知识点已经学会；
- 不容易追踪教材证据和遗漏内容。

Elenchi 会在备课时建立课程卡片，课堂中主要使用本课知识点、教材证据和当前焦点小节原文，从而减少噪声并提高教学聚焦度。

# 四、知识点与质量备课

## 14. Elenchi 所说的“知识点”是什么？

知识点不是一个关键词，也不是随意截取的一段文本，而是一个可以被单独教学和验证的原子命题。

一个知识点通常包含：

- 一句清晰的可教陈述；
- 知识类型，例如概念、原理、程序或事实；
- 所属章节和小节；
- 在教材中的顺序；
- 一至三条教材原文证据。

例如，下面是较好的知识点：

> 监督学习使用带有目标标签的训练样本。

它可以被单独提问、要求解释，也可以在课堂中判断是否掌握。

而“监督学习这一章”不是一个适合直接评估的知识点，因为它包含太多不同命题。

## 15. 知识点是 AI 自己想出来的吗？

AI 会提出知识点候选，但 Elenchi 不会无条件接受模型输出。

知识点形成大致经过以下步骤：

1. 将章节分成小节；
2. 把连续的小节批量交给知识点抽取器；
3. 要求模型输出结构化知识点；
4. 要求每个知识点携带教材逐字证据；
5. 检查证据是否确实存在于对应小节原文；
6. 对未覆盖的教学信息进行反向审计；
7. 必要时针对缺口重新抽取；
8. 最后再把知识点编排成课程。

因此，模型负责提出候选内容，程序负责验证证据、顺序、闭集和持久化。

## 16. 为什么知识点必须绑定教材逐字证据？

逐字证据有三个作用：

1. **减少幻觉：** 防止 AI 把教材之外的常识当成教材内容；
2. **方便复核：** 用户可以回到原文检查知识点依据；
3. **限定课堂范围：** 课堂追问优先围绕本课知识点和教材证据展开。

如果模型生成的引文不是对应小节原文中的连续片段，系统会认为该结果不合格，并尝试纠正。多次纠正仍失败时，会显式报告备课失败，而不是悄悄保存不可靠结果。

## 17. 什么是“覆盖审计”？

知识点抽取只能说明“抽取出了什么”，不能保证“教材的重要内容没有遗漏”。

覆盖审计会反过来检查每个小节：

> 是否有包含定义、原理、方法、因果关系或重要数值等教学信息的原文片段，没有被任何知识点覆盖？

如果发现缺口，系统会针对该小节进行一次补充抽取。补充后仍有缺口时，该小节会被标记为部分覆盖。

这是一种诚实的质量提示，不代表教材一定错误，也不代表系统已经保证 100% 完备。

## 18. 什么叫“质量备课”？

质量备课不是生成一篇看起来流畅的章节摘要，而是同时检查：

- 内容是否被合理分节；
- 知识点是否是单一、可教、可评估的命题；
- 知识点是否有逐字教材证据；
- 重要内容是否可能被遗漏；
- 知识点是否保持教材顺序；
- 每堂课的知识点数量是否适合学习；
- 课堂是否能够据此判断掌握、推进和收尾。

备课的结果可能是：

- **已准备：** 课程和知识点已生成；
- **已准备，但部分覆盖：** 课程可以使用，但有小节存在未完全确认的内容，建议对照原文；
- **备课失败：** 当前结果未通过必要校验，需要重试或检查教材、AI 服务配置。

## 19. 为什么一堂课通常只有 3–7 个知识点？

这是为了控制一次学习的认知负担。

课程不是越长越好。如果一堂课包含整章几十个知识点，学习者很难在对话中逐一解释、应用和巩固，AI 也更容易失焦。

因此，Elenchi 通常以 3–7 个知识点安排一堂课，目标容量约为 5 个。较小的章节可以少于 3 个；课程会尽量保持教材顺序，并优先在小节边界附近切分。

## 20. 为什么有时会看到“自动编排”？

课程编排首先会让 AI 根据主题相近性提出分组建议，然后由程序检查：

- 是否遗漏知识点；
- 是否重复分配；
- 是否改变教材顺序；
- 是否超出课程容量。

如果 AI 的分组方案多次不符合规则，Elenchi 会使用确定性的顺序装箱方式生成课程，并标记为自动编排。

这意味着课程仍然可以使用，但分组可能更偏向机械地遵循文档顺序，而不是最优的主题分组。

## 21. 备课失败后会自动重试吗？

不会无限自动重试。

对单个模型输出的格式或证据错误，系统会在管线内部进行有限次数的纠正；如果整个章节备课失败，用户需要明确点击“重试”。

这样设计是为了避免未经用户确认地反复消耗模型额度，也让失败状态对用户可见。

# 五、苏格拉底式课堂

## 22. 课堂是怎样开始的？

进入一堂课时，Elenchi 会创建或复用与该课程关联的学习 session，并生成开场消息。

开场通常包含：

- 上一堂课的带走摘要（如果有）；
- 本堂课的学习目标；
- 一个回忆问题或针对第一个知识点的引导问题。

系统不会一开始就把整堂课的答案讲完，而是先让你调动已有理解。

## 23. 为什么 AI 不直接告诉我答案？

因为“看懂解释”不等于“能够独立回忆和使用”。

Elenchi 默认采用延迟答案的教学方式：先让你回忆、解释、举例或推理，只有在你确实卡住时才逐步提供帮助。

它不是“永远不告诉答案”。更准确的说法是：

> **默认延迟答案，必要时逐步提示和受控解释。**

## 24. 提示等级 H0–H4 是什么？

提示等级表示 AI 介入的强度：

| 等级 | 方式 |
|---|---|
| H0 | 只提出开放问题，不给方向 |
| H1 | 缩小问题范围，让问题更具体 |
| H2 | 提供关系、方向或局部提示 |
| H3 | 提供局部事实、反例或中间步骤 |
| H4 | 给出简短解释或推导，然后要求你复述 |

如果你的回答质量下降、连续没有覆盖新的知识点、重复同一误解，或者你明确表示卡住，提示等级可能逐步提高。

## 25. AI 会根据我的错误类型调整问题吗？

会。课堂不是简单判断“对”或“错”，还会关注你的理由、完整性和误解。

例如：

- 结论错误且暴露隐含假设：追问假设；
- 结论正确但没有理由：追问证据和推理链；
- 结论过于绝对：给出反例或边界情形；
- 只会解释定义但不会使用：换一个情境要求应用；
- 跑题：礼貌地拉回本课目标；
- 连续卡住：逐步提高提示强度。

每一轮通常只执行一个教学动作，并提出一个主要问题，避免一次塞入多个新概念。

## 26. AI 的回答一定不会超出教材吗？

系统会尽量将课堂限制在本课知识点、逐字证据和当前焦点小节原文范围内，并要求模型在无法确认时明确说明不确定。

但任何依赖生成模型的系统都不能保证绝对没有错误。对于：

- 医疗、法律、财务等高风险内容；
- 教材本身存在错误的内容；
- 数学公式、代码或复杂推导；
- 你发现与原文不一致的解释；

请回到教材原文并进行独立核验，不要把 AI 的回答当作权威结论。

## 27. 我可以直接要求 AI 解释吗？

可以。如果你明确请求解释，系统可以进入受控解释动作。但解释之后通常还会要求你用自己的话复述或应用，以确认你不是只看过答案。

如果只是暂时想得到一点帮助，也可以先尝试回答“我目前的理解是……”，这样系统更容易判断你卡在哪里。

## 28. 我回答失败时，输入会丢失吗？

设计目标是：AI 回复失败时不丢失你已经输入的内容，界面应允许你检查、修改并重新发送。

如果遇到网络中断、模型超时或服务返回错误，请先确认输入框中的内容仍在，再选择重试。若实际版本出现输入丢失，请记录发生步骤和错误信息并反馈。

# 六、学习进度与课程完成

## 29. Elenchi 如何判断我掌握了一个知识点？

当前课堂采用结构化评估，而不是只看关键词是否出现。

通常需要同时满足：

- 回答内容正确；
- 推理或理由可靠；
- 回答完整，没有遗漏关键条件。

仅仅提到一个术语、猜中结论，或把答案原样复制出来，不一定代表真正掌握。

## 30. 为什么进度显示“已掌握 X / Y 个知识点”，而不是分数？

因为单一的百分比容易制造虚假的精确感。

Elenchi 当前更关注：

```text
本课计划 5 个知识点，已掌握 3 个
```

这让你知道还剩哪些内容需要学习，但不把复杂的理解状态简化成一个看似精确的 72%。

## 31. 课程什么时候会推进到下一个知识点？

当当前回答通过评估并且当前知识点达到掌握条件后，系统会根据本课计划，选择下一个尚未掌握的知识点。

推进顺序默认遵循课程中的知识点顺序，不由模型临时跳到任意主题。

## 32. 课程什么时候结束？

当本课计划中的知识点全部达到掌握条件时，系统会进入课程收尾流程。

收尾通常会：

- 要求你复述本课核心内容；
- 汇总已经掌握的知识点；
- 记录仍存在的误解或遗留问题；
- 生成本课带走摘要；
- 将相关进度保存到教材学习状态中。

## 33. 下一堂课会记得上一堂课吗？

课程之间可以通过上一堂课的带走摘要衔接。下一堂课开场时，系统可以先让你回忆上一课的关键内容，再引入新的学习目标。

这不是完整的长期个人画像，也不是跨所有教材的智能复习系统；它主要用于同一本教材、同一学习路径内的课程承接。

## 34. 我可以跳过前面的课程直接开始后面的课程吗？

当前课程顺序通常是固定的，尚未完成前一堂课时，后续课程可能处于锁定状态。

这样做是为了避免用户在基础知识尚未验证的情况下直接跳到后续内容。已经进入过的课程可以根据当前版本的 session 规则重新查看，但已完成课程的完整“重修”能力不属于当前 MVP 的主要范围。

## 35. 旧版本的课堂记录还能继续学习吗？

历史 session 可以查看和导出，但旧的、没有关联新课程的 session 可能是只读的，不能继续发送新的课堂消息。

这是为了避免旧版课堂状态和新版课程卡、知识点掌握逻辑混用。

# 七、闪卡与课堂记录

## 36. 课后可以生成闪卡吗？

可以。Elenchi 可以根据当前完整课堂对话生成闪卡，并将闪卡保存到本机。

闪卡通常包括：

- 问题；
- 答案；
- 解释或补充说明。

如果课堂对话没有产生足够明确的可记忆内容，系统也可能返回空的闪卡结果。

## 37. 闪卡生成会自动去重吗？

当前闪卡生成是**追加式**的，尚不承诺智能去重。

如果你多次根据同一堂课生成闪卡，可能会出现相似或重复内容。你可以在生成后编辑或删除不需要的闪卡。

## 38. 我可以编辑或删除闪卡吗？

可以。当前支持：

- 查看闪卡；
- 修改题目、答案或解释；
- 删除闪卡；
- 导出闪卡 Markdown。

删除是破坏性操作，执行前应确认你不再需要该闪卡。

## 39. 可以导出课堂记录吗？

可以。课堂实录可以导出为 Markdown，内容包括：

- 教材和章节信息；
- 课堂开始时间；
- 按时间排序的学习者和 AI 消息。

浏览器打印视图也可以用于保存为 PDF，但 PDF 主要依赖浏览器的打印能力，不代表 Elenchi 服务端提供了独立的 PDF 生成器。

## 40. 删除教材会发生什么？

删除教材会连带删除与它关联的内容，例如：

- 章节；
- 备课结果；
- 课程；
- 课堂记录；
- 闪卡；
- 相关学习进度。

这是不可逆操作，删除前请确认已经导出需要保留的课堂记录和闪卡。

# 八、数据、隐私与 AI 服务

## 41. “本地优先”是什么意思？

本地优先表示 Elenchi 的主要数据保存在运行 Elenchi 的设备及其本地数据目录中，包括：

- 导入的教材；
- 章节和课程准备结果；
- 课堂 session 与消息；
- 学习进度；
- 闪卡；
- AI 服务设置。

当前产品不以账号、云同步或多人协作为前提。

## 42. 本地优先是否等于完全离线？

不等于。

Elenchi 的数据存储优先在本机，但备课、回答评估、AI 回复和闪卡生成需要调用你配置的 AI 服务。因此，相关教材片段、课堂回答或对话上下文可能被发送到该服务。

是否保存、如何处理和是否用于训练，取决于你使用的 AI 服务商及其隐私政策。使用敏感教材前，请先确认服务商的数据处理条款。

## 43. API Key 保存在哪里？

API Key 保存于 Elenchi 的本机设置数据中。界面读取设置时只返回脱敏预览，不显示完整 Key。

当前产品文档不应把 API Key 描述为“已经加密保存”的能力承诺。请注意：

- 保护好运行 Elenchi 的设备和用户账户；
- 不要将本机数据目录提交到 Git 或公开分享；
- 不要在截图、日志或问题反馈中暴露完整 Key；
- 如果怀疑泄露，请立即在服务商处撤销并更换。

## 44. Elenchi 会把整本教材发送给 AI 服务吗？

课堂阶段主要围绕当前课程卡、当前知识点证据和焦点小节原文组织上下文，而不是每一轮都无边界发送整本教材。

备课阶段仍需要处理章节内容，以完成分节、知识点抽取、覆盖审计和课程编排。实际发送范围、调用次数和费用取决于教材长度、备课流程和你配置的模型服务。

## 45. Elenchi 会把我的数据同步到云端吗？

当前产品不以 Elenchi 自己的账号系统或云同步为前提。数据主要写入本机。

但你配置的外部 AI 服务可能接收到用于模型调用的内容。请将“本地保存”和“不会离开设备”区分开来。

# 九、故障处理

## 46. 测试连接失败怎么办？

请依次检查：

1. Base URL 是否填写为服务要求的兼容接口地址；
2. API Key 是否有效；
3. 模型名称是否正确且有访问权限；
4. 本机网络是否可以访问该服务；
5. 服务商是否发生限流、维护或地区限制；
6. 是否误将模型名称、完整请求 URL 或其他字段填入 Base URL。

修正后重新测试连接。不要在问题反馈中公开完整 API Key。

## 47. 备课一直失败怎么办？

建议按以下顺序处理：

1. 查看错误提示，确认是连接、模型、格式还是内容问题；
2. 确认 AI 服务仍然可用；
3. 检查 Markdown 标题和正文是否完整；
4. 先尝试较短章节；
5. 重新点击备课重试。

如果是模型输出结构或教材证据校验失败，系统会尝试有限次数的纠正；最终仍失败时会保留失败状态，等待用户主动重试。

## 48. 为什么备课完成了，但提示部分覆盖？

这表示课程已经生成，但至少有一个小节的部分教学信息仍没有被系统充分绑定到知识点。

你仍然可以继续学习，但建议：

- 对照该章节原文；
- 把重要遗漏内容作为课堂中主动提出的问题；
- 如果结果明显不合理，调整教材结构或模型设置后重试。

“部分覆盖”是风险提示，不是“完全备课成功”的同义词。

## 49. 发送回答后 AI 没有回复怎么办？

可能原因包括：

- AI 服务暂时不可用；
- 网络超时；
- 模型返回空内容；
- 评估结果没有通过结构校验；
- 流式回答中断。

请先确认你的输入仍在输入框中，再重试。如果反复失败，请保存错误信息，并确认 Base URL、模型和服务商状态。

## 50. 为什么课堂进度没有更新？

只有在一次回答完成评估、教学回复成功生成并成功保存后，课堂状态才会更新。

如果中间任何一步失败，系统可能不会保存这次交换，以避免出现“用户看见了回复，但进度没有对应证据”或“进度更新了，但课堂消息没有保存”的不一致状态。

## 51. AI 回复不准确怎么办？

请把教材原文作为首要依据。你可以：

- 指出回答与哪段原文不一致；
- 要求 AI 回到当前知识点重新解释；
- 用自己的回答说明你认为哪里有问题；
- 重新检查该知识点的教材证据；
- 对高风险内容进行独立验证。

Elenchi 的课程卡和证据约束用于降低偏离教材的概率，但不会消除生成式 AI 的全部错误。

# 十一、产品理念与后续方向

## 52. Elenchi 最核心的产品原则是什么？

可以概括为五点：

1. **学习者推理优先：** 先让学习者想，再提供帮助；
2. **受控解释：** 卡住时逐步增加提示，而不是永远拒绝解释；
3. **一次只做一件事：** 一轮对话聚焦一个教学动作和一个认知任务；
4. **教材是边界：** 课堂优先依据当前课程知识点和教材证据；
5. **进度要诚实：** 以可解释的知识点计数为主，不制造虚假精度。

## 53. 为什么 Elenchi 要把备课做成独立层？

因为“如何回复下一句话”和“这一章应该教什么”是两个不同问题。

如果没有课程准备层，AI 可能：

- 临时发明知识点；
- 在整章内容中自由跳跃；
- 无法判断是否遗漏；
- 无法稳定计算课程进度；
- 每次课堂都从零开始。

独立的备课层先建立知识点、证据和课程计划，课堂引擎再在这个边界内执行教学策略。

## 54. Elenchi 后续可能会发展什么？

在不改变当前核心方向的前提下，后续可能探索：

- 更丰富的教材格式导入；
- 更好的备课质量解释和人工修订；
- 跨课程和跨教材的间隔复习；
- 更完整的学习目标与计划；
- 知识点依赖关系；
- 更细粒度的复习与掌握证据；
- 更多模型协议和本地模型适配；
- 更完善的导出、打印和跨设备能力。

这些属于产品方向，不代表当前版本已经支持，也不应被理解为固定发布日期承诺。

## 55. 我应该怎样获得更好的学习效果？

建议采用以下方式：

- 导入结构清楚、标题层级合理的 Markdown 教材；
- 尽量使用完整的小节，不要只导入零散句子；
- 回答时先写出自己的理解，不要只回复“知道了”；
- 说明理由、条件、反例和应用场景；
- 卡住时明确说出“我不确定的是……”；
- 发现 AI 与原文不一致时及时指出；
- 课后查看课堂记录和闪卡；
- 对部分覆盖的小节主动回看教材；
- 对高风险或专业内容进行独立核验。

Elenchi 最适合把它当成一位会追问的学习伙伴，而不是替你完成学习的答案机器。
